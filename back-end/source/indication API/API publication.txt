## 2. Détail d'une publication

**`GET /api/publications/<uuid>/`** — Public

### Réponse `200 OK`

```json
{
  "success": true,
  "data": {
    "id": "...",
    "titre": "Coucher de soleil sur les Calanques",
    "description": "Prise à Marseille en juillet.",
    "image_affichee": "http://localhost:8000/media/publications/filigranes/wm_photo.jpg",
    "est_vendue": false,
    "type": "vente",
    "prix": "120.00",
    "categories": [{ "id": "...", "nom": "Nature", "description": null }],
    "tags": [{ "id": "...", "nom": "golden-hour" }],
    "nombre_likes": 34,
    "a_like": false,
    "photographe_nom": "Marie Martin",
    "photographe_photo": "http://localhost:8000/media/profils/marie.jpg",
    "photographe_id": "...",
    "is_active": true,
    "created_at": "2024-11-15T10:30:00Z",
    "updated_at": "2024-11-15T11:00:00Z"
  }
}
```

> 💡 **`image_affichee`** est l'unique champ image à utiliser côté React :
> - Tant que `est_vendue = false` → c'est la version **avec filigrane**
> - Quand `est_vendue = true` → c'est automatiquement la version **originale sans filigrane**
>
> Tu n'as pas à gérer cette logique côté frontend — le backend s'en occupe.

## 3. Créer une publication *(photographe)*

**`POST /api/publications/`** — 🔒 Photographe requis  
**Content-Type :** `multipart/form-data`

> ⚠️ **Le photographe doit avoir un abonnement actif.** Voir [droits selon abonnement](#droits-de-publication-selon-abonnement).

| Champ | Type | Requis | Description |
|---|---|---|---|
| `titre` | string | ✅ | |
| `description` | string | ❌ | |
| `image_originale` | file | ✅ | L'image de la publication |
| `type` | string | ❌ | `"publicite"` (défaut) ou `"vente"` |
| `prix` | number | ⚠️ | Obligatoire si `type = "vente"` |
| `categories` | UUID[] | ❌ | Liste d'UUIDs de catégories existantes |
| `tags` | string[] | ❌ | Liste de noms de tags |
| `is_active` | boolean | ❌ | `true` par défaut |

> ⚠️ **Envoi des listes en FormData :**
> ```javascript
> formData.append("categories", "uuid-1");
> formData.append("tags", "golden-hour");
> formData.append("tags", "nature");
> ```

> 🎨 Le filigrane est généré **automatiquement** côté serveur à l'upload. Tu envoies uniquement `image_originale`.

### Réponse `201 Created`

```json
{
  "success": true,
  "message": "Publication créée.",
  "data": { /* PublicationDetail */ }
}
```

### Réponses erreur

```json
{ "success": false, "errors": "Vous devez avoir un abonnement actif pour publier." }
{ "success": false, "errors": "La publication de type 'vente' est réservée aux abonnés Premium." }
{ "success": false, "errors": { "prix": ["Le prix est obligatoire pour une publication de type vente."] } }
```

## Filtres et recherche

| Paramètre | Valeur | Exemple |
|---|---|---|
| `type` | `publicite` ou `vente` | `?type=vente` |
| `categorie` | UUID d'une catégorie | `?categorie=<uuid>` |
| `tag` | nom du tag | `?tag=golden-hour` |
| `photographe` | UUID du profil photographe | `?photographe=<uuid>` |
| `q` | recherche libre | `?q=mariage+paris` |
| `page` | numéro de page | `?page=2` |
| `page_size` | nombre par page (max 50) | `?page_size=24` |

## Droits de publication selon abonnement

| Abonnement | `publicite` | `vente` |
|---|---|---|
| Aucun / expiré | ❌ | ❌ |
| Basic | ✅ | ❌ |
| Premium | ✅ | ✅ |

> Si le photographe n'a pas d'abonnement actif, l'API retourne `400` avec :
> ```json
> { "success": false, "errors": "Vous devez avoir un abonnement actif pour publier." }
> ```

## Structure des objets

```typescript
interface Publication {
  id: string;
  titre: string;
  description: string | null;
  image_affichee: string;   // URL unique — filigrane OU originale selon est_vendue
  est_vendue: boolean;      // true = photo achetée, image_affichee = originale sans filigrane
  type: "publicite" | "vente";
  prix: string | null;
  categories: Categorie[];
  tags: Tag[];
  nombre_likes: number;
  a_like: boolean;
  photographe_nom: string;
  photographe_photo: string | null;
  photographe_id: string;   // détail uniquement
  is_active: boolean;
  created_at: string;
  updated_at: string;       // détail uniquement
}

interface Categorie {
  id: string;
  nom: string;
  description: string | null;
}

interface Tag {
  id: string;
  nom: string;
}
```

## Téléchargement d'une photo

**`GET /api/publications/<uuid>/telecharger/`** — Public

Retourne le fichier image directement en téléchargement (`Content-Disposition: attachment`).

### Logique côté serveur

| Situation | Image servie |
|---|---|
| Utilisateur a acheté la photo | ✅ Originale sans filigrane |
| Connecté mais pas acheté | 🔒 Avec filigrane |
| Non connecté | 🔒 Avec filigrane |

> ⚠️ Le token JWT ne peut pas être envoyé en header sur un lien direct `<a href="...">`. Il faut utiliser `fetch` avec `blob()` pour les téléchargements authentifiés.

### Méthode 1 — fetch + blob (recommandée)

```javascript
const telecharger = async (publicationId) => {
  const token = localStorage.getItem("access_token");

  const response = await fetch(
    `http://localhost:8000/api/publications/${publicationId}/telecharger/`,
    {
      headers: token ? { Authorization: `Bearer ${token}` } : {},
    }
  );

  if (!response.ok) {
    console.error("Erreur téléchargement");
    return;
  }

  // Récupérer le nom du fichier depuis le header Content-Disposition
  const disposition = response.headers.get("Content-Disposition");
  const nomFichier  = disposition
    ? disposition.split("filename=")[1]?.replace(/"/g, "")
    : "photo.jpg";

  // Créer un lien de téléchargement temporaire
  const blob = await response.blob();
  const url  = URL.createObjectURL(blob);
  const link = document.createElement("a");
  link.href     = url;
  link.download = nomFichier;
  link.click();
  URL.revokeObjectURL(url);
};
```

### Méthode 2 — lien direct (non connecté uniquement)

```javascript
// Pour un utilisateur non connecté — reçoit toujours le filigrane
const telechargerSansAuth = (publicationId) => {
  window.open(
    `http://localhost:8000/api/publications/${publicationId}/telecharger/`,
    "_blank"
  );
};
```

### Bouton React complet

```jsx
<button onClick={() => telecharger(publication.id)}>
  {aAchete ? "Télécharger (original)" : "Télécharger"}
</button>
```

> 💡 `aAchete` peut être déterminé en vérifiant l'historique des commandes de l'utilisateur — si la publication apparaît dans une commande avec `status: "paye"`, l'utilisateur a acheté la photo.

## Commentaires

### Liste des commentaires d'une publication

**`GET /api/publications/<uuid>/commentaires/`** — Public, pas de token requis

### Réponse `200 OK`

```json
{
  "success": true,
  "pagination": {
    "total": 5,
    "pages": 1,
    "page_actuelle": 1,
    "page_size": 12,
    "suivante": null,
    "precedente": null
  },
  "data": [
    {
      "id": "uuid-commentaire",
      "auteur_id": "uuid-user",
      "auteur_nom": "Jean Dupont",
      "auteur_photo": "http://localhost:8000/media/profils/jean.jpg",
      "contenu": "Magnifique photo !",
      "nombre_reponses": 1,
      "est_auteur": true,
      "reponses": [
        {
          "id": "uuid-reponse",
          "auteur_nom": "Marie Martin",
          "auteur_photo": null,
          "contenu": "Merci beaucoup !",
          "created_at": "2024-11-15T10:35:00Z"
        }
      ],
      "created_at": "2024-11-15T10:30:00Z",
      "updated_at": "2024-11-15T10:30:00Z"
    }
  ]
}
```

> 💡 `est_auteur` vaut `true` si l'utilisateur connecté est l'auteur du commentaire — utilise ce champ pour afficher ou masquer le bouton supprimer. Si l'utilisateur n'est pas connecté, `est_auteur` vaut toujours `false`.

### Ajouter un commentaire

**`POST /api/publications/<uuid>/commentaires/`** — 🔒 Authentifié requis

#### Commentaire simple

```json
{
  "contenu": "Magnifique photo !"
}
```

#### Réponse à un commentaire existant

```json
{
  "contenu": "Merci beaucoup !",
  "parent_id": "uuid-du-commentaire-parent"
}
```

| Champ | Type | Requis | Description |
|---|---|---|---|
| `contenu` | string | ✅ | Texte du commentaire (max 1000 caractères) |
| `parent_id` | UUID | ❌ | UUID du commentaire parent pour une réponse |

### Réponse `201 Created`

```json
{
  "success": true,
  "message": "Commentaire ajouté.",
  "data": {
    "id": "...",
    "auteur_id": "...",
    "auteur_nom": "Jean Dupont",
    "auteur_photo": null,
    "contenu": "Magnifique photo !",
    "nombre_reponses": 0,
    "est_auteur": true,
    "reponses": [],
    "created_at": "2024-11-15T10:30:00Z",
    "updated_at": "2024-11-15T10:30:00Z"
  }
}
```

### Réponses erreur `400`

```json
{ "success": false, "message": "Vous ne pouvez pas répondre à une réponse." }
{ "success": false, "message": "Commentaire parent introuvable." }
```

---

### Supprimer un commentaire

**`DELETE /api/publications/commentaires/<uuid>/`** — 🔒 Authentifié requis

> Autorisé uniquement pour **l'auteur du commentaire** ou le **photographe propriétaire de la publication**.

Aucun corps requis.

### Réponse `200 OK`

```json
{
  "success": true,
  "message": "Commentaire supprimé."
}
```

### Réponse erreur `403`

```json
{
  "success": false,
  "message": "Vous n'êtes pas autorisé à supprimer ce commentaire."
}
```

> ⚠️ Supprimer un commentaire parent supprime aussi toutes ses réponses automatiquement (cascade).

---

### Like / Unlike un commentaire

**`POST /api/publications/commentaires/<uuid>/like/`** — 🔒 Authentifié requis

Toggle : si déjà liké → unlike, sinon → like. Aucun corps requis.

### Réponse `200 OK`

```json
{
  "success": true,
  "data": {
    "liked": true,
    "nombre_likes": 5
  }
}
```

> 💡 `a_like` est déjà inclus dans chaque commentaire retourné par la liste — utilise-le pour afficher l'état initial du bouton like sans appel supplémentaire.

```typescript
interface Commentaire {
  id: string;

  auteur_photo: string | null;

  reponses: Reponse[];
  created_at: string;
  updated_at: string;
}

interface Reponse {
  id: string;
  auteur_nom: string;
  auteur_photo: string | null;
  contenu: string;
  created_at: string;
}

interface StatutLikeCommentaire {
  liked: boolean;
  nombre_likes: number;
}
```
